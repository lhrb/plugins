# Significant Slice 1 decisions

- Keep the shell in `audiotestreference/` as a bounded, standalone experiment, not a reusable editor framework. DSP depends only on Rust; plugin and helper adapters depend inward on it. No code imports another plugin's internals.
- Use experimental CLAP ID `org.audio-test-reference.shell-experiment`, name `AudioTestReference (Shell Experiment)`, version `0.1.0`. This is not the final product identity or a promise of preset/session compatibility. It exposes no parameters or mode state. Do not use it in production sessions.
- Pin unmodified NIH-plug to `de421011f41a6d10fc8c7a6084e4f4dee0143683` and GPUI to `0.2.2`; commit Cargo.lock. Copy only helper discovery/ownership and X11 reparenting from NAM. Do not copy NAM DSP, assets, protocol, vendor tree or packaging framework. Unlike NAM, this shell stores no async GUI executor or GUI context, so it needs no ownership-cycle patch.
- Retain the proven X11 adapter's attachment-time mapping and its known NIH-plug `show`/`hide` limitation for this experiment. Do not silently expand into wrapper maintenance before manual Bitwig evidence. Hosts requiring successful visibility callbacks remain unsupported; revise or stop if Bitwig requires them.
- Bundle a separate executable beside the CLAP module. GPUI owns its event loop outside the host. A one-way anonymous pipe carries only a latched input-fault status; no audio, settings, paths or general IPC API. Closing the editor kills/reaps its helper and joins its status writer outside audio processing. There is no standalone device, GUI-to-DSP control or network behavior.
- Ship a debug-profile artifact for the first mechanism/manual-host checkpoint to bound build cost. An optional release build exists, but release performance and resource qualification are not claimed. Build-cache reuse is optional and creates no source dependency on NAM.
